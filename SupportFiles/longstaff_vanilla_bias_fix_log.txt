Request addressed

Improve the vanilla American put pricing workflow by diagnosing and reducing the upward LSMC bias relative to the direct American benchmark, then rerun the benchmark and robustness tables. Also save a persistent review log under SupportFiles.

Diagnosis summary
-----------------
The main cause of the inflated vanilla LSMC values was the classic same-path Longstaff bias:
1. Continuation-value regressions were fit on the same path set used for exercise decisions.
2. The stopping rule was then effectively valued in-sample, which tends to overstate performance.
3. The effect was especially visible in longer-maturity / higher-volatility cases.

Code changes made
-----------------
1. Updated lsm_engine.py
   - Added richer regression diagnostics to LSMRegressionStep.
   - Added optional path-mask arguments and minimum regression-path threshold support.
   - Preserved reusable generic engine behavior.

2. Updated run_longstaff_vanilla.py
   - Switched main vanilla benchmark pricing to a two-pass design:
     a. fit policy on one simulated path set
     b. evaluate policy on an independent path set
   - Retained same-path mode explicitly for the in-sample vs out-of-sample diagnostic table.
   - Added benchmark columns to capture fit/eval separation:
     - lsmc_fit_price
     - lsmc_fit_minus_eval
     - fit_price / eval_price / corresponding stderrs
     - split_policy / fit_seed / eval_seed
   - Re-ran benchmark and robustness tables using the improved pricing design.

Interpretation
--------------
The major upward distortion was indeed coming from in-sample valuation. The two-pass policy valuation materially tightened the benchmark alignment, especially in the high-volatility long-maturity case where the gap shrank from roughly +0.93 to about +0.07.

Remaining caveats
-----------------
- The improved design is more honest and more stable, but some cases now undershoot the FD benchmark.
- That is acceptable as a diagnostic outcome: same-path values were too optimistic, while independent valuation removes much of that optimism.
- Additional tightening could still be pursued via basis redesign, alternative state scaling, or cross-fitting / multi-fold splitting.
