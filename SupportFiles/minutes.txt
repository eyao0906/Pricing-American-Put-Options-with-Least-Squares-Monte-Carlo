4. WHAT THE CURRENT CODE DOES
================================================================================

4.1 data_loader.py
- Downloads AAPL adjusted close prices from Yahoo Finance using yfinance.
- Uses 5 years of daily data.
- Estimates annualized volatility from daily log returns:
    sigma = std(log returns) * sqrt(252)
- Uses ^IRX as a simple risk-free proxy (13-week T-bill annualized percent).
- If ^IRX fails, falls back to r = 0.04.

4.2 lsmc.py
- Simulates geometric Brownian motion paths.
- Prices an American put using Longstaff-Schwartz backward induction.
- Uses Laguerre-style polynomial basis functions.
- Regresses discounted continuation cashflows on basis functions of normalized stock price x = S_t / K.
- Uses in-the-money paths at each decision time.
- Outputs:
  - estimated price
  - Monte Carlo standard error
  - exercise boundary array (summary proxy from exercised path states)

4.3 tsitsiklis_vanroy.py
- Implements a simplified Tsitsiklis–Van Roy style fitted value iteration comparator.
- Uses polynomial basis [1, x, x^2, x^3].
- Regresses continuation value on ALL paths rather than only ITM paths.
- Outputs:
  - price
  - stderr currently set to NaN

4.4 run_study.py
- Pulls market data and estimated inputs.
- Sets:
  - ticker = AAPL
  - maturity = 1 year
  - steps = 50
  - n_paths = 100,000
- Prices 3 American puts with strikes:
  - 0.9 * spot
  - 1.0 * spot
  - 1.1 * spot
- Also computes Black-Scholes European put values as a reference benchmark.
- Saves:
  - pricing_results.csv
  - historical_price.png
  - exercise_boundary.png
  - model_comparison.png

7. PIVOTS / ROLES OF THE REFERENCE PAPERS
================================================================================

This section is critical for the next AI. The two papers should not be treated as redundant.
They play DIFFERENT roles in the project.

----------------------------------------
7.1 Longstaff & Schwartz (2001) — practical pivot
----------------------------------------

Main project role:
- The practical “anchor” paper.
- This should be the main implemented methodology and the main narrative backbone.

Core idea:
- For American options, continuation value is unknown.
- Simulate paths under the risk-neutral measure.
- At each exercise date going backward:
  - look at continuation cashflows realized later on each path,
  - regress those discounted future cashflows on basis functions of the current state,
  - use the fitted regression as an estimate of conditional continuation value,
  - exercise if immediate payoff > estimated continuation value.

Why it matters:
- Avoids state-space explosion from trees / finite difference in multifactor settings.
- Very flexible for path dependence and high-dimensional problems.
- Easy to implement relative to more complex numerical methods.

Important practical details from the paper:
- Regression is usually done only on in-the-money paths.
- Basis function choice matters, but the paper emphasizes that low-order bases often work surprisingly well.
- The paper validates the method on multiple examples:
  - vanilla American put,
  - path-dependent exotic examples,
  - jump-diffusion,
  - multifactor interest-rate problems.

How this maps to current project:
- Current lsmc.py is directly in this tradition.
- Current project should probably present LSMC as the main methodology actually “replicated”.

----------------------------------------
7.2 Tsitsiklis & Van Roy (2001) — theoretical / ADP pivot
----------------------------------------

Main project role:
- The conceptual and theoretical extension / comparator paper.
- Useful for positioning the project as more than just “we coded LSMC”.

Core idea:
- Frame pricing as optimal stopping / dynamic programming.
- Approximate value functions (or Q-functions / continuation values) with parameterized regressions.
- Analyze approximate value iteration and regression-based dynamic programming.
- Show that state sampling matters a lot:
  - arbitrary representative states can produce error growth that becomes very bad with horizon,
  - representative states drawn from simulated risk-neutral trajectories keep the error bounded.
- Also explores approximation across both state and time.

Why it matters:
- Gives theoretical support for regression-based simulation methods.
- Explains why trajectory-based sampling is not just a coding convenience; it is structurally important.
- Offers a more general ADP / fitted-value-iteration viewpoint than the classical LSMC recipe.

How this maps to current project:
- Current tsitsiklis_vanroy.py is a compact educational comparator, not a full theoretical reproduction.
- The report should be careful not to over-claim full replication of all TVR theory.
- Better framing:
  “We implement a simplified TVR-style fitted value iteration benchmark to compare with LSMC and to illustrate how different regression-DP choices affect pricing.”

----------------------------------------
7.3 Practical project pivot between the two papers
----------------------------------------

Best combined interpretation for the final project:
- Longstaff-Schwartz = practical regression-on-paths method that is easy to implement and widely used.
- Tsitsiklis–Van Roy = broader dynamic programming and approximation lens explaining why regression-based simulation works and where it can go wrong.

This means the project should likely be framed as:

“This project studies American option pricing through two related regression-based simulation paradigms:
(1) LSMC in the Longstaff–Schwartz sense as the main practical algorithm,
and
(2) a simplified Tsitsiklis–Van Roy style dynamic-programming comparator used to interpret the problem from an approximate value iteration viewpoint.”

That is a strong framing because it:
- matches the papers,
- matches the current code,
- gives both a practical and theoretical angle,
- makes the project look more mature.

8. IMPORTANT LIMITATIONS / ISSUES TO ACKNOWLEDGE
================================================================================

These points should almost certainly appear in the report and/or be addressed by the next AI.

1) Current implementation is only single-asset vanilla American PUT.
- This is much simpler than many examples in the papers.
- The project must explicitly say this is a controlled testbed / pedagogical replication.

2) Real-world calibration is simplistic.
- Volatility estimated from historical AAPL returns.
- Risk-free rate from ^IRX proxy.
- Assumes constant sigma and constant r under GBM.
- No dividend treatment.
- No option-market implied calibration.

3) TVR implementation is simplified.
- It is not a complete theoretical reproduction of the full paper.
- It may exhibit approximation bias or materially different behavior due to implementation choices.

4) No benchmark yet against “ground truth”.
- For a vanilla American put under GBM, a binomial tree or finite difference benchmark is feasible.
- This should probably be added to validate LSMC and diagnose TVR behavior.

5) Regression-specification risk.
- Basis choice may matter.
- Degree choice may matter.
- ITM-only regression vs all-path regression matters.

6) Statistical robustness is still weak.
- One seed per method currently.
- No repetition study across seeds.
- No path-count sensitivity analysis.
- No time-step sensitivity analysis.
- No basis-degree sensitivity analysis.

7) Exercise boundary is only an empirical approximation.
- The current boundary array is a heuristic summary from exercised path states.
- It is useful for plotting, but it is not an exact theoretical free boundary.
